# RDL_生命らしさ評価指針
*実装付属文書 / rdl_village / DRAFT v0.9*
*参照：RDL_階層構造モジュール / 神経力学的基層構造 / RDL_簡易村シミュレーター / RDL_NPC行動決定システム*

**位置づけ**：本文書は Tier 体系の文書ではない。
同フォルダの `rdl_village` 実装がどこへ向かうかを定める、コード付属の評価軸である。
記載された実測値もこの実装・この村での観測であり、体系的な主張ではない。
一般化に耐える内容が固まった時点で、T4 応用層への昇格を検討する。

## ■ 0. 一文定義

> 仮想世界シミュレーションが目指すのは生命らしさであり、それは生存を含みつつ生存に還元されない、環境との関係の中で構造を維持しながら更新し続ける状態である。

```text
生命らしさ = Vector(
  生存,
  行動レパートリー,
  個体分岐,
  意味の個体差,
  生活構造の日次変化,
  破断位置の多様性
)
```

生命らしさは単一のスカラーではない。
圧縮すると、何が失われているかを判別できなくなる。

## ■ 1. 目的

本文書は、RDL的エージェント・仮想世界の開発において、**何を良くなったとみなすか**を定める。

必要になった理由は具体的である。開発中、評価指標が明示されていなかったため、測定可能で分かりやすい**生存率が事実上の目的関数にすり替わった**。その結果、次の誤った結論が出た。

```text
測定：退屈（D4）を有効にすると生存率が下がる（静止環境で 99.0% → 98.4%）
結論：退屈は純コストである
```

この結論は、生存を目的に置いた場合にのみ正しい。同じ実行を生活構造の日次変化で測ると、退屈は寄与していた。

**指標を書かないと、測りやすいものが目的になる。**
本文書はその漂流を止めるために置く。

## ■ 2. B――成立させたい状態

RDL_簡易村シミュレーター §2 の `B_village` を評価側から言い直す。

```text
B_eval = 個体が、不完全な知覚と記憶のもとで、
         環境と他個体との関係から行動を生成し、
         その結果が自身と環境へ残り、
         日ごとに少しずつ異なる構造を形成し続けている状態を、
         外部から観測可能な形で確認できること
```

「うまくやっている」ことではない。「**生きているように動いている**」ことを見る。

## ■ 3. 生存の位置づけ

生存は生命らしさの**必要条件**であり、**目的関数ではない**。

### 3.1 なぜ目的関数にできないか

生存だけを最大化すると、最も安全な構造は「変化しないこと」になる。

```text
生存最大化
  → 予測の当たる行動のみを反復
  → 探索・跳躍・関係形成の抑制
  → 構造が固定される
  → 死んだ構造が最高得点を得る
```

これは RDL_NPC行動決定システム §12-2 が破断条件として挙げる「Hが高いほど必ず乱数行動が増えると仮定する」の裏返しである。乱数を排して固着させれば生存は上がるが、それは SILN の更新が止まった状態にすぎない。

### 3.2 生存率100%が意味しないこと

**生存率100%は「何も起きていない」と区別がつかない。**

実測では、機構を何も足さない素の村が生存48/48（100%）で、同時に生活構造の日次変化が最小だった。全員が予定どおり動き、誰も破断せず、何も変わらない村である。

生存は**下限として**見る。個体が理由なく死に続けるなら世界設計が壊れているが、全員が安全に生き続けることは達成ではない。

### 3.2.0 生存率は環境の過酷性と対で読む（v0.9 で追加）

前項は不正確だった。**生存率100%が意味を持つのは、過酷性がゼロでない世界においてのみである。**

`rdl_village` の既定世界には、捕食者・致死的な天候・季節・病気・事故のいずれも存在しない。死因は身体変数が限界へ達することだけで、資源は再生する。

```text
環境過酷性 = 0
　→ 生存率100%は正常な帰結であって、異常ではない
　→ 生存の軸は情報を持たない
　→ §3.3 の「賭け金」も存在しない
```

したがって、この世界で生存率を報告することにはほとんど意味がない。同じ理由で `fear` 軸が 0.0% のまま動かないのも、供給機構の不在ではなく**脅威の不在**である（§6.9）。

```text
規則：生存率は、その世界の過酷性と対にして読む。
　　　過酷性ゼロの世界での生存率100%を、未解決の変動として扱わない。
```

実例として、破断検査は生存率の未説明の変動を三版にわたり未解決として持ち越したが、そのうち100%到達については説明が最初から世界の側にあった。**個体の挙動を説明しようとして、世界の設定を見ていなかった。**

過酷性を持たせるなら、§4.2.2 に従い構造から出す。「難しくする規則」ではなく、自身の駆動を持つ捕食者や、個体が予測して備えられる季節として置く。

### 3.2.1 下限の水準

`rdl_village` v0.1 の既定世界（6個体・640tick・10日）では **80%** を下限とする。

```text
生存率 ≥ 80%   ： 他の軸で判断する
生存率 < 80%   ： 世界設計を見直す対象とする
```

**この数値は現環境に依存する。** 世界側の性質（資源密度・陳腐化速度・移動距離・時間帯の長さ）を変えたら、下限も引き直す。資源が長期休眠する変動環境では別の水準になる。普遍定数ではなく、この村の運用値として扱う。

下限を割ったときの対処は**世界設計の見直し**であって、生存を上げる機構の追加ではない。後者をやると §3.1 の「死んだ構造が最高得点を得る」方向へ戻る。

```text
下限割れ → 資源配置・距離・代謝速度・時間帯長を見る
        → 「生存を助ける行動」を足すのではない
```

下限は超えていれば十分であり、余裕を増やすことに価値はない。100% は §3.2 のとおり「何も起きていない」と区別がつかない。

**ただし、下限までの余裕を予算として扱わない。**

数値の下限は逆向きの失敗様式を作る。「主軸が上がるなら生存はどこまで下げてよいか」という問いに、80という数字が答えを与えてしまう。§7-1 は生存を目的関数にすることを禁じるが、下限の明示は生存を**消費可能な資源**に変える。

```text
規則：生存率の変動は、方向によらず原因を特定してから受け入れる。
      下限を超えていることは、原因を調べない理由にならない。
```

原因が特定できない変動は、下限内であっても未解決の破断として扱う。

**上昇も同じである。** 望ましい方向へ動いたことは、系を理解していることを意味しない。説明できない改善は、説明できない悪化と同じだけ未解決である。

実例として v0.1 実装では二度の未説明の変動が生じた。

```text
give 経路の開放時   93.8% → 89.6%   低下、原因未特定
tick解決の相分離後  89.6% → 95.8%   上昇、原因未特定
```

後者は「解決順のせいで範囲外と誤判定されていた会話が成立するようになったため」と推測されているが、切り分けられていない。前者と同じく未解決として扱う。

### 3.3 生存が持つ役割

生存は、行動に**賭け金**を与えるために要る。

失敗しても何も失われない世界では、選択に意味が生じない。生存の脅威は、探索・関係形成・跳躍が「割に合うかどうか」を成立させる基盤として機能する。

```text
生存 = 目的ではなく、他の指標が意味を持つための土台
```

## ■ 4. 生命らしさの分解

単一値に圧縮しない。理由は H_vec と同じである。

RDL_簡易村シミュレーター §19-9 は「Hを単一値に圧縮し、破断位置を判別できなくする」を破断条件としている。評価指標も同型で、圧縮すると**どこが貧しいのか**が判別できなくなる。

### 4.1 六つの軸

| 軸 | 何を見るか | 貧しい状態 |
|---|---|---|
| 生存 | 個体が構造を維持できているか（下限80%、§3.2.1） | 理由のない全滅 |
| 行動レパートリー | 行為の種類と分布の広さ | 全員が一日中同じ行為 |
| 個体分岐 | 個体間で行動分布がどれだけ違うか | 全員が同じ生活 |
| 意味の個体差 | 同じ対象が個体ごとに違う意味を持つか | 場所が全員に同じ意味 |
| 日次変化 | 生活構造が日ごとに変わるか | 完全な反復ループ |
| 破断位置の多様性 | Hがどのチャネルで立つか | 単一チャネルへの偏り |

### 4.2 主軸と従軸

すべてを同時に最大化することはできない。軸は互いに干渉する。

`B_village` の定義が「日ごとに少しずつ異なる生活構造を形成する状態」である以上、

```text
主軸：日次変化・個体分岐
従軸：レパートリー・意味の個体差・破断位置の多様性
下限：生存
```

とする。従軸が下がっても主軸が上がっているなら、それは前進とみなす。

ただし**主軸どうしが逆を向くことがある**。繁殖動機の追加では、個体分岐が上がる一方（0.0732 → 0.0745）で日次変化が下がった（0.2127 → 0.1914）。番った相手と行動を共にするため、個体間は分岐し、個体内の生活は固定化する。

この場合に一方を優先する規則は置かない。**両方を報告し、どちらを取るかをその都度の設計判断として明示する。** 規則で自動化すると、指標の合成が判断の代わりになる。

### 4.2.1 日次変化の測り方（v0.3 で改訂）

初版の定義は無効だった。記録として残す。

```text
初版：村全体の行動種別分布について、隣接する日のJSダイバージェンス

検証（8シード）
  観測             0.0441
  ノイズ床         0.0313   ← 同一分布からの再抽出でこれだけ出る
  別々の村同士の差 0.0109   ← 構造が違う村の方が、同じ村の隣接日より近い
```

村全体の行動種別比は「全員が食べて飲んで寝る」という生理ループに支配され、村が違ってもほぼ同じになる。**構造は「何をしたか」ではなく「どこで」に宿っていた。** さらに村全体で集約すると、個体間の逆向きの変化が相殺されていた。

```text
改訂：個体ごとに、キーを (行動, 場所) として隣接日のJSダイバージェンスを取り、
      同一分布からの再抽出で求めたノイズ床を差し引いた超過分を用いる

  観測 0.3892 / ノイズ床 0.2189（1.78倍）
  別々の村を識別する力は行動種別のみの9倍
```

### 4.2.2 行動は構造から出す。重みで押し切らない

ある行動を増やしたいとき、二つの道がある。

```text
構造を足す   身体が衰える／予測が外れる／資源が尽きる
　　　　　　 → その帰結として行動が変わる

重みを回す   その行動のスコア係数を上げる
　　　　　　 → 行動は増えるが、増やしたのは自分である
```

**後者を選ぶと、観測しているのは自分が入れた定数になる。**

世界側で行動を調整するのも同じ誤りである。「暗いと採餌効率が落ちる」といった規則は、
個体に理由を持たせず外から結果を作る。村§19-7（村全体の雰囲気を中央変数で操作する）
§19-12（イベント脚本で個体判断を上書きする）が禁じているのと同型である。

実例として、薄暮の退避を成立させるために退避候補の重みを調整したが、

```text
重み 0.0（機構なし）  生存 98%  日次変化 0.2318  ← 最良
重み 1.0              生存 94%  日次変化 0.2302
重み 1.6              生存 81%  日次変化 0.2167
重み 2.4              生存 92%  日次変化 0.2220
```

主軸が最も高いのは機構を切ったときであり、しかも単調ですらなかった。
調整していたのは信号ではなくノイズだった。機構は撤去した。

同じ局面で、身体の衰弱に勾配を入れる（空腹・渇きが限界まで無影響だったのを、
連続的に速度と視界を落とすよう変える）ほうは、重みを一切触らずに

```text
生存 85.4% → 91.7%   平均空腹率 0.481 → 0.431   日次変化 0.2130 → 0.2220
```

を得た。**閾値を書く代わりに、身体の構造が余裕を保つ理由を生んだ。**

```text
規則：行動が足りないとき、まず構造の欠けを探す。
　　　重みと世界規則は、構造で説明できないと確かめてから触る。
```

### 4.3 意味の個体差について

この軸は RDL_簡易村シミュレーター §6.2「場所ラベルは共有されても、意味は共有されない」の直接の検査である。

意味が分岐するには、同じ場所での**出来事**が個体ごとに違う必要がある。資源の有無だけを経験している間は、全員がほぼ同じ意味を形成する。拒否された場所、番った場所、奪われた場所といった個体固有の出来事が接続されて初めて分岐する。

## ■ 5. 測定してわかっていること

以下は RDL_簡易村シミュレーター v0.1 実装（6個体・640tick・8〜32シード）での実測である。確定した法則ではなく、この実装・この村での観測として扱う。

### 5.1 探索の効果は世界に依存する

自発熱（退屈／D4）による外的探索は、環境によって符号が変わった。

```text
静止環境（未踏が尽きた村）  → 生存 98.4%（D4なし 99.0%）  払い損
変動環境（資源が長期休眠）  → 生存 96.4%（D4なし 91.1%）  回収
```

資源信念の**数**は両環境でほぼ同じ（差 -0.06）。増えたのは知識量ではなく、古い記憶が使えなくなる前に代替を持っている確率だった。

効いていたのは資源の**量**ではなく、**陳腐化速度と未踏量**である。

### 5.2 外的探索と内的探索は報われる条件が逆

自発熱の出口を内側（思考的探索）へ向けると、依存関係が反転した。

```text
外的探索：世界が変動しているとき報われる（未踏と陳腐化があるから）
内的探索：世界が安定しているとき報われる（安定だから外挿が当たる）
```

両方を無条件に有効にすると、変動環境では内的探索が外的探索の枠を食い、外的探索のみより悪化した（96.4% → 93.8%）。

**内的モデルはその世界のモデルである。** 静止した世界は静止したモデルを作るので、内的探索も辺境を持たない。世界への依存は回避されず、緩和されるだけだった。

### 5.3 基層と現環境のずれ

RDL_階層構造モジュール §1 は基層構造を「進化的選択圧によって形成された」層と定義する。したがって基層パラメータは**祖先環境の性質を圧縮した定数**であり、現環境がその性質を持たなければ回収がない。

繁殖動機はその極端な場合である。繁殖機構（出産・継承）を実装しない世界では、回収チャネル自体が存在しない。

これは病理ではなく、§1 の時間スケール差からくる構造的帰結として読む。

### 5.3.1 三機構の寄与（v0.3 で再測定）

初版は旧 day_drift で「三機構すべてが日次変化に寄与し、単調に増えた（0.0341 → 0.0405）」と記録した。差はノイズ床の分散以下であり、**あれは何も示していなかった**。

改訂した指標で16シード再測定した結果は次のとおり。

| 条件 | 日次変化 | 個体分岐 |
|---|---|---|
| 素の村（D4なし） | 0.1770±0.0290 | 0.0621±0.0254 |
| ＋退屈 D4 | **0.2108**±0.0244 | 0.0651±0.0179 |
| ＋思考的探索 | 0.2127±0.0208 | **0.0732**±0.0170 |
| ＋繁殖動機 | 0.1914±0.0298 | **0.0745**±0.0219 |

```text
D4        日次変化 +19%。旧指標では差がノイズだったが、正しく測ると実在した
思考的探索 日次変化には上乗せしない。個体分岐は上げる
繁殖動機   日次変化を下げ、個体分岐を上げる（旧指標では逆に見えていた）
```

繁殖動機については**符号が反転した**。旧指標での「日次変化に寄与」は誤りである。

### 5.4 動機を足すと別の行為が枯れる（原因帰属を訂正）

繁殖動機を追加すると、行動の**種類**は増えた（7 → 9）が、分布の**均等さ**は下がった（0.720 → 0.674）。求愛と接近が資源行動の枠を取ったためである。

**訂正**：初版は、同時に観測された `obligation` 軸の消失（1.5% → 0%）も同じ原因に帰属させたが、これは誤りだった。破断検査により、求愛を無効化しても `give` は0回のままであることが確認された。原因は押しのけではなく、**初期配置による経路閉塞**である（material が grove の2ノードのみで採取がほぼ起きず、`TRANSFER_RANGE` も狭い）。

```text
現象の記述（新しい動機は既存の行為と有限の行動枠を奪い合う）は
レパートリー均等さの低下によって支持される。
obligation の消失はこの証拠にならない。
```

同時に観測された二つの変化を、一方の原因へまとめて帰属させた例として残す。**追加時は既存軸の稼働率を測るだけでなく、低下した軸ごとに反事実で原因を切り分ける。**

## ■ 6. 測定上の落とし穴

実際に踏んだものだけを挙げる。

### 6.1 減衰する量を最終値で測らない

`irritation` `territoriality` のような減衰する関係軸は、実行終了時のスナップショットではほぼゼロになる。減衰率0.985で640tickなら 0.985^640 ≒ 0 であり、何を足しても消える。

```text
誤：実行終了時の値
正：実行中のピーク、または時間積分
```

### 6.2 サンプル数を確保する

5シードで得た符号が16シードで反転した事例がある。生存率のように個体単位で離散的な指標は、差が数個体の水準になるため特に振れる。

**符号が反転しうる差を報告するときは、必ずシード数と分散を併記する。**

### 6.3 飽和した軸は差を隠す

既知場所数のように上限が近い指標は、機構の効果があっても天井で潰れる。世界側に余地がない指標を主軸にしない。

### 6.4 指標が現象ではなく更新頻度を測っていないか

蓄積量を持つ指標は、蓄積源の到来頻度と減衰率の比で上限が決まる。誤差 E を k tick に一度受け取るチャネルの定常ピークは

```text
H_peak = gain · E / (1 − decay^k)
```

であり、`decay=0.9` / `θ_eff≈1.2` / 正規化済み `E≤1.0` では `k ≤ 2.7` でなければ原理的に閾値へ届かない。

実測では `relation` チャネルが観測時の平均誤差 0.407（全チャネル中最大）でありながら、観測頻度 12.2% のため8シードで跳躍1回だった。**誤差の大きさではなく更新頻度で落ちている。**

したがって「破断位置の多様性」（§4.1）は、そのままでは

```text
どこで破断したか  ではなく
どのチャネルが毎tick観測されるか
```

を測る。低頻度の事象は、一件あたりが十分大きくても指標に現れない。

これは §7-3（測定しやすい指標を、測定したい性質の代理として無検証で使う）が、**本指針の定義した指標そのものに該当した**例である。

### 6.5 交絡を修正すると、先行する反事実テストは無効になりうる

破断検査は「同族候補の本数制限で主軸 divergence が +19%」を反事実で示したが、これは `body` チャネルの単位不整合が跳躍の33%を占めていた状態での測定だった。単位不整合を修正した後に24シードで再測定すると、主軸への効果は消え（差はすべて標準偏差内）、残ったのは従軸レパートリーへの効果のみだった。

```text
反事実テストは、その時点の交絡構造の上でしか成立しない。
交絡を一つ潰したら、それ以前の反事実は再実行する。
```

### 6.6 指標をノイズ床と対比したか

有限標本から計算する分布間距離は、**同一分布から引いても正の値を取る**。件数が少ないほど大きくなる。

```text
検査手順
  1. 観測した分布から、同じ件数を再抽出した二標本を作る
  2. その距離を複数回平均し、ノイズ床とする
  3. 観測値から床を差し引いた超過分を報告する
```

床の1.4倍程度の観測値は、何も測っていない可能性がある。実際、旧 day_drift（観測0.0441 / 床0.0313）がこれに該当した。

**差を報告する前に、その差がノイズ床の分散を超えているかを確認する。**

### 6.7 集約が個体差を打ち消していないか

全体で集約すると、個体間の逆向きの変化が相殺される。個体Aが採集から会話へ移り、個体Bが逆へ移れば、全体の分布は動かない。

```text
誤：村全体で分布を作ってから比較する
正：個体ごとに比較してから平均する
```

実測では、個体別に取ると村全体の3倍の信号が出た（0.1347 対 0.0441）。

### 6.8 検査装置自身が同じ破断を持っていないか

本指針の規則は、測定コードにも等しく適用される。

実例として、回帰検査の `test_relation_axes_are_live` は docstring に「ピークで測る」と書きながら、実際には実行終了時の値を読んでいた。**§6.1 が名指しで禁じている操作を、検査自身がやっていた。**

```text
検査が通っていることは、検査が正しいことを意味しない。
検査対象へ向けた規則を、検査自身へも向ける。
```

比較範囲の狭さも同種である。順序独立性の検査は位置と空腹だけを比べていた。範囲を広げた途端に検査自身のバグが露呈した。**通っていたのは、比較していなかったからである。**

### 6.9 軸が動かないことから機構の不在を推論しない

ある軸の稼働率が低いとき、原因は二つある。

```text
供給機構が存在しない
既にある供給経路が塞がれている
```

観測値からはこの二つを区別できない。実例として `territoriality` 7.1% の低さを「妨害行為が未実装だから」と帰属させたが、実際は資源競合の敗者更新が `continue` で飛ばされていただけで、配線を直すと 49.0% になった。

```text
規則：軸が不活性なら、まず既存の供給経路を末端まで辿る。
      機構の追加を提案するのはその後にする。
```

### 6.10 記録したことを、処理したこととして扱わない

交絡や破断を文書へ書いても、測定コードは何も変わらない。

実例として、破断検査 v0.5 は「死亡個体の短いログが分岐を水増しする」と記録したが、`richness.measure()` は生死を区別せず計算し続け、以後の報告もその値を主軸として引用し続けた。

```text
文書：この指標には交絡がある
実装：交絡したままの値を返す
報告：その値を引用する
```

**記録は、次に同じ値を引用したときの歯止めにならない。** 交絡を見つけたら、同じ差分で測定コードを直すか、直せないなら指標名にその旨を含める（`divergence_all` のように）。

同型の誤りとして、文書へ書いた機構を実装したものとして扱うことがある。v0.5 は `Place.objects` について「置く／取るを実装した」と書いたが、呼び出し箇所が一つも無かった。§6.9 が言う「構造があるのか配線が切れているのか判別できない」状態を、文書自身が「実装済み」と宣言して固定していた。

```text
規則：文書が実装の状態を主張するときは、呼び出し箇所の有無で裏を取る。
```

### 6.11 指標が構造を識別できるか

「日ごとの変化」を測る指標が、そもそも**別々の構造を区別できるか**を先に確認する。

```text
検査：明らかに構造の違う二つの実行（別シード）の距離を測る
      それが同一実行内の隣接日の距離より小さければ、
      その指標は構造を捉えていない
```

旧 day_drift はこの検査に落ちた（別村間0.0109 < 同一村の隣接日0.0441）。

## ■ 7. 破断条件

次の場合、本指針は機能を失う。

1. 生存率を目的関数として最適化する
2. 生命らしさを単一のスコアへ圧縮し、どこが貧しいかを判別できなくする
3. 測定しやすい指標を、測定したい性質の代理として無検証で使う
4. 指標を後から選び、望む結論が出た軸だけを報告する
5. 減衰する量を最終スナップショットで評価する
6. 機構を追加したとき、既存軸の稼働率を測らない
7. 個体を「うまくやっている」度合いで評価し、個体差を誤差として扱う
8. 観測者の全知情報を評価に使い、個体の予測場との乖離を見ない
9. 世界側の性質を固定したまま、機構の優劣を一般化する
10. 指標をノイズ床と対比せず、生の分布間距離をそのまま差として報告する
11. 指標が別々の構造を識別できるかを検査しないまま主軸に据える
12. 主軸どうしが逆を向いたとき、合成規則で自動的に判定する（判断の代替にしない）
13. 望ましい方向への変化を、説明されたものとして扱う
14. 下限までの余裕を、消費してよい予算として扱う
15. 測定コードへ本指針の規則を適用しない
15-2. 行動を増やすために、構造ではなく重み係数を回す
15-3. 個体に理由を持たせず、世界側の規則で行動を形づくる
16. 軸の不活性から、供給機構の不在を推論する
16-2. 文書へ書いた機構を、実装したものとして扱う
16-3. 交絡を記録したことをもって、処理したものとして扱う
17. 不変条件を実行終了時にだけ検査する
18. 破断条件そのものを更新せず、初期の指針に固着する

---

## ■ 8. 構造耐久証明書

### 有効範囲

- 小規模な生活・生態シミュレーションの評価
- RDL的エージェントへの機構追加の可否判断
- 基層パラメータと環境の適合検査
- 実装変更前後の比較測定

### 現時点で保証しないもの

- 生命の定義そのもの
- 生物学的妥当性
- 六軸が必要十分であること
- 軸の重み付けの唯一性
- 大規模個体数での成立

### 残存構造

本指針が破綻しても、次は個別に再利用できる。

- 生存を下限として扱い、目的関数から外す操作
- 評価指標をベクトルのまま保持する原則
- 主軸・従軸・下限の三層分け
- 減衰量をピークで測る規則
- 機構追加時に既存軸の稼働率を併測する規則
- 分布間距離を再抽出ノイズ床との超過分で扱う操作
- 個体別に計算してから平均する規則（集約による相殺の回避）
- 「別々の構造を識別できるか」による指標の事前検査
- 世界側の性質（陳腐化速度・未踏量・回収チャネル）を独立変数として明示する枠

---

## ■ 9. 一文圧縮

> 目指すのは生命らしさであり、生存はその必要条件だが目的関数ではない。生存だけを最大化すれば最も安全な構造は変化しないことになり、死んだ構造が最高得点を得る。
