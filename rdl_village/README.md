# RDL_village

RDL的NPCによる簡易村シミュレーター。Python実装、外部依存なし。

設計は次の二文書に従う。

- `RDL_簡易村シミュレーター`（T4 / DRAFT v0.1）
- `RDL_NPC行動決定システム`（T4 / DRAFT v0.3）

係数の出発点は [rdl_system/profiles](../rdl_system/profiles/) の reference profile。

---

## 実行

```bash
python -m rdl_village 640 7        # 640tick（10日）、seed 7
python -m rdl_village.test_regression
```

同じ seed・同じ tick 数から同じ snapshot を得る（村§18）。
別プロセスでも一致する。

## 実装している主な機構

- **物理世界と個体予測場の分離**（村§3.2）。NPC側モジュールは物理世界の真値を先読みしない
- **同時解決**（村§14末尾）。tick解決を五相へ分離し、個体ごとに独立した乱数列を持つ
- **説明つき誤差**。説明のつく予測差はξへ流さず、残差だけが不定剰余として蓄積する
- **熱の固着と再前景化**。処理されないHは M_lat として構造へ沈み、再会で熱へ戻る
- **自発熱（退屈）**（階層構造§2）。誤差が少ない状態が続くと仮想熱が立ち、探索を促す
- **思考的探索**。身体を動かさずに構造の中を探索する。産物は M_lat 止まり
- **繁殖動機**。繁殖機構（出産・継承）は村§15.3 に従い含めない
- **備蓄**（村§6.1 Place.objects, §7.3 置く／取る）

## 付属文書

### `RDL_生命らしさ評価指針.md`

何を「良くなった」とみなすかを定める。生存を目的関数から外し、
生命らしさを六軸ベクトルへ分解する。

> 生存だけを最大化すれば最も安全な構造は変化しないことになり、
> 死んだ構造が最高得点を得る。

測定上の落とし穴（ノイズ床、集約による相殺、減衰量の測り方、
検査装置自身の破断）を実例つきで記録している。

### `破断検査.md`

実装が枠組み自身の基準に照らしてどこで崩れているかの記録。
成功した修正だけでなく、**失敗した試行列を過程ごと**残している。

> 帰らない理由を五手ぶん探したが、正しい問いは
> 「帰ることに何の得があるか」であり、得の無い世界に動機を足していた。

## 現状と限界

この村には環境過酷性が無い（捕食者・致死的天候・季節・病気のいずれも無い）。
そのため生存率は情報を持たず、`fear` 軸は動かず、行動に賭け金が乗らない。

また 640tick（10日）走らせているが、**1日を超える周期の変動が世界に存在しない**。
個体側は階層構造§1 の4層を持つが、世界側に対応する時間スケールが無いため、
中核構造と基層構造が形成される相手を持たない。

未解決として記録しているもの：

- 破断位置が `goal` チャネルへ偏る（観測頻度の高いチャネルが先に閾値へ届く）
- `gather`（後で使うために採る）がほとんど駆動しない
- 夜に留まるコストが存在せず、夜が生活の相として立たない
