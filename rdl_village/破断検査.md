*実装付属文書 / rdl_village / DRAFT v0.7*

**位置づけ**：本文書は Tier 体系の文書ではない。
`rdl_village` 実装に対して破断検査を実行し、どこで枠組み自身の基準に照らして崩れているかを記録するコード付属文書である。
記載された数値はこの実装・この村・この係数での観測であり、体系的な主張ではない。

**検査条件**：8〜16シード × 640tick × 6個体。
**参照点**：コミット `58759af`
**回帰検査**：`python -m rdl_village.test_regression`（28項目）

## ■ 1. 前版の訂正

### 1.1 実装を上回る主張をしていた（v0.5 §2.4, §5.2）

v0.5 は次のように書いた。

```text
Place.objects / stock / gather は
村§6.1・§7.3 の「置く／取る」を実装した
```

**「置く」も「場所から取る」も実装されていなかった。** `Place.store()` `take_stored()` `stored()` は定義されていたが、コード中に呼び出し箇所が一つも無かった。実際に動いていたのは

```text
資源ノードから採る → 個人の携行へ入れる → 個人が使う
```

だけで、場所は一度も介在していない。

これは指針§6.9 に自分で書いた「使われない場を置くと、構造があるのか配線が切れているのかが判別できなくなる」に、**本文書自身が該当していた**。しかも文書がそれを「実装済み」と宣言していたため、判別できないどころか誤った前提が固定されていた。

対応：撤回ではなく実装で埋めた。

```text
deposit 110回 / take_stored 100回（8シード）
```

### 1.2 交絡を記録しながら測定コードを直していなかった（v0.5 §4）

v0.5 は、空間拡大時に `divergence` が上がったのは死亡個体の短いログによる交絡だと記録した。**記録しただけだった。** `richness.measure()` は生死を区別せず全個体で計算し続けており、以後の測定値もすべてその値だった。

```text
文書：この指標には死亡による交絡がある
実装：交絡したままの値を返し続ける
報告：その値を主軸として引用し続ける
```

**破断を記録することは、破断を直すことではない。** 記録は、次に同じ値を引用したときに気づく手がかりにはならなかった。

対応：`divergence`（生存者のみ）と `divergence_all` を分離した。

## ■ 2. 物質保存が破れていた
**確信度：高（実測）**

資源配分が `node.amount` を直接読み、`node.state` を確認していなかった。さらに `node.take()` の戻り値を無視し、事前計算した配分をそのまま個体へ与えていた。

```text
state = regenerating
node.amount = 10
node.take(10) → 0.0（取れない）
個体へ与えた量 → 10
ノード残量    → 10 のまま
```

**世界に存在しない資源が個体へ流入していた。** 16シード×640tickで7回発生。

同種の破れがもう一つあった。候補側は `expected_outcome["amount"]` に信念量・携行余地・予測不足量を反映していたが、解決側は常に `INTAKE_LIMIT` を要求していた。

```text
gather の期待量 5   携行の空き 5
ノードから消えた量 34   実際に蓄えられた量 5   消失 29
結果は gained=5 で誤差0、完全成功として学習される
```

世界から29が消えたことは、どのチャネルにも入らなかった。

対応：`node.usable` を確認し、`take()` の実取得量へ按分し直す。要求量は候補の期待量で頭打ちにする。回帰検査に収支の不変条件を追加した。

```text
世界から減った量 ≧ 個体の携行 + 場所の保管
```

## ■ 3. 提案しただけで状態が変わっていた
**確信度：高（反転テスト実測）**

v0.4 で対話を二段階にしたが、第一段階の `_propose_dialogue()` が `open()` と `reply()` を呼んでいた。これらは純粋計算ではない。

```text
ターン数 / recent / last_talk_t を更新
語彙ノードの usage_count・confidence・phase を更新
個体乱数を消費
```

したがって実際の構造は「全提案を固定状態から計算」ではなく、

```text
一件目の提案が対話状態を変更 → 二件目は変更後の状態から提案
```

だった。提案順を反転すると、seed 5・320tick で Aki の最終位置が `(16.56, 16.86)` から `(9.93, 12.74)`、hunger が 30.0 から 74.8 まで分岐した。

上限超過で不成立になった会話も、提案時点で語彙ノードと会話履歴を既に変えていた。**起きなかった会話の痕跡が残る。**

対応：順序を逆にした。

```text
競合を先に決める（受け手が talk_gradient で選ぶ）
  → 採用された組だけ発話を生成
  → 確定
```

あわせて、話者の名前順ではなく受け手が選ぶ形にしたため、恒常的な名前優位も外れた。

```text
残存構造：二段階化は「計算してから確定する」形にしなければ意味がない。
　　　　　計算側が状態を変えるなら、順序を逆にして
　　　　　「確定してから計算する」ほうが正しい。
```

## ■ 4. その他の処理

| # | 破断 | 対応 |
|---|---|---|
| 4 | 完全重なりの分離に組み込み `hash()` を使用。プロセスごとに乱数化され再現しない | blake2b の安定ハッシュへ |
| 5 | 世界時計の `day` と評価側の `_day_of` が1日ずれる | `VillageClock.decision_tick` を単一定義とし、評価側の補正を撤去 |
| 6 | `use_stock` が身体の不足を見ず、超過分が消えたうえ完全成功として学習 | 不足で頭打ち。`register_prediction` を `use_stock` / `wait` へも接続 |

指摘6には付随する破れがあった。`register_prediction()` が `use_resource` だけを対象としていたため、**蓄えからの摂取と待機は body チャネルの予測差に一度も現れていなかった**。自然実行で1シードあたり約19回使われる経路である。

## ■ 6. 残っているもの

### 6.1 生存100%
**解決（未解決として持ち越していたのが誤り）**

v0.4 §5.2 以来、生存率の未説明の変動として持ち越していたが、**説明は最初から世界の側にあった**。

```text
既定世界に存在しないもの
　捕食者 / 致死的な天候 / 季節 / 病気 / 事故
死因は身体変数が限界へ達することだけ。資源は再生する。

環境過酷性 = 0  →  生存率100%は正常な帰結
```

個体の挙動を説明しようとして、世界の設定を見ていなかった。

同じ事実が三つの症状として別々に記録されていたことも判明した。

| 記録していた症状 | 実体 |
|---|---|
| 生存100%（§6.1） | 過酷性ゼロ |
| `fear` が0.0%のまま（v0.4 §5.3） | 脅威源なし |
| 賭け金が無い（指針§3.3） | 同上 |

指針§3.2.0 として「生存率は環境の過酷性と対で読む」を追加した。

過酷性を持たせるかどうかは設計判断であり、破断ではない。持たせるなら指針§4.2.2 に従い、難易度の規則ではなく構造（自身の駆動を持つ捕食者、個体が予測できる季節）として置く。

### 6.2 夜に留まるコストが存在しない
**未解決**（v0.5 §5.1）

個体側の動機では五手で否定された。世界側に置くのは指針§4.2.2 に反する。入れるなら季節のように**個体が予測して対処できる変動**として入れる。それなら `gather` も同時に駆動する。

### 6.3 leap:goal が最大供給源
**未解決**（v0.2 §2.2 以来）

### 6.4 `repertoire` の低下

0.6417 → 0.5958。行動種別が増えた（`deposit` `take_stored` が加わった）一方で分布が偏った。指針§5.4 の「新しい行為は既存の行為と有限の行動枠を奪い合う」に該当する可能性があるが、切り分けていない。

## ■ 7. 破断条件

1. 反事実テストを少シードで実行し、符号を確定させる
2. 修正候補の順位を、主軸への効きではなく実装の容易さで並べ替える
3. 「破断が見つかった」ことをもって実装の失敗と判定する
4. 本検査で見つからなかった領域を、破断がない領域と同一視する
5. 指標の再定義を、望ましい数値が出る方向へ選ぶ
6. 修正後の再測定を、修正した軸だけで行う
7. 定義の異なる指標値を並べて増減を判定する
8. 稼働率を測定方法を併記せずに報告する
9. 実装のバージョンを固定しないまま指標の定義を変える
10. 順序独立性を、処理順の固定だけで主張する
11. 望ましい方向への変化を、説明されたものとして扱う
12. 回帰検査の失敗を、検査側の閾値調整で通す
13. 入力順への非依存を、同時性の成立と同一視する
14. 不変条件を実行終了時にだけ検査する
15. 軸が動いていないことから、機構の不在を推論する
16. 検査装置自身が検査対象と同じ破断を持ちうることを忘れる
17. 「なぜ起きないか」を問う前に「起きることに何の得があるか」を測らない
18. 失敗した試行を記録から落とし、成功した手だけを残す
19. 各段の推論が妥当であることを、問いの立て方が妥当である証拠とする
20. **文書へ書いた機構を、実装したものとして扱う**
21. **交絡を記録したことをもって、交絡を処理したものとして扱う**
22. **計算段階が状態を変えないことを、確かめずに前提とする**
23. **資源の収支を、与えた側と受け取った側の両方で検算しない**
24. **個体の挙動として説明しようとして、世界の設定を確認しない**
25. 本検査自身を更新せず、過去の破断リストに固着する

## ■ 8. 構造耐久証明書

### 有効範囲

- `rdl_village` 参照点 `58759af` における破断位置の同定
- 蓄積型指標を持つ小規模エージェント実装での観測頻度バイアスの検査
- 同時解決を主張する系における順序独立性・同時性の検査
- 資源の生成・消失を伴う実装での収支検査

### 現時点で保証しないもの

- v0.1 からの改善量（v0.2 §2.1 により測定不能）
- §6.4 の `repertoire` 低下の原因
- 個体数・tick数・縮尺を変えた場合の同一結論
- 破断候補の列挙が網羅的であること

### 残存構造

- `H_peak = gain·E / (1 − decay^k)` による跳躍可能な観測頻度の上限計算
- 「決定論的 ≠ 同時的」「テスト通過 ≠ 不変条件の成立」という二つの取り違え
- **「文書に書いた ≠ 実装した」「記録した ≠ 直した」という第三の取り違え**
- 処理されない熱が構造へ固着し、再会で熱へ戻るという H の扱い
- 段差を勾配へ変えると、閾値を書かずに個体が余裕を保つようになる、という型
- 自発探索の回収条件は「未踏があること」と「戻れる余裕があること」の積である
- 失敗した試行列そのものが、成功した一手より強い制約を残す
- **二段階化は、計算側が状態を変えないことを確かめて初めて意味を持つ**
- **資源の収支は、与えた側と受け取った側の両方で検算する**
- 軸の不活性から機構の不在を推論しない、という規律
